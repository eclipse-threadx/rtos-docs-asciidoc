= Chapter 5: USBX OTG
:description: USBX OTG protocol hooks require a controller-specific implementation for runtime role switching.

USBX contains OTG protocol hooks for Host Negotiation Protocol (HNP), status requests, and role changes. The current USBX repository does not include a ready-to-use OTG controller driver, so enabling `UX_OTG_SUPPORT` alone does not make runtime host/device switching work on a board. In particular, no i.MX RT1024 OTG integration is provided.

An OTG integration must provide controller-specific role detection, VBUS control, interrupt handling, and host/device stack transitions. The regular threaded USBX build uses ThreadX. `UX_STANDALONE` removes USBX's RTOS dependency, but the repository does not include a FreeRTOS adapter or a controller-specific OTG integration.

There are four categories of functions for an OTG controller in addition to the usual host/device functions.

* VBUS specific functions
* Start and Stop of the controller
* USB role manager
* Interrupt handlers

== VBUS functions

Each controller needs to have a VBUS manager to change the state of VBUS based on power management requirements. Usually this function only performs turning on or off VBUS

== Start and Stop the controller

Unlike a regular USB implementation, OTG requires the host and/or the device stack to be activated and deactivated when the role changes.

== USB role Manager

The USB role manager receives commands to change the state of the USB. There are several states that need transitions to and from those given in the table below.

|===
| State | Value | Description

| UX_OTG_IDLE
| 0
| The device is Idle. Not connected to anything

| UX_OTG_IDLE_TO_HOST
| 1
| Device is connected with type A connector

| UX_OTG_IDLE_TO_SLAVE
| 2
| Device is connected with type B connector

| UX_OTG_HOST_TO_IDLE
| 3
| Host device got disconnected

| UX_OTG_HOST_TO_SLAVE
| 4
| Role swap from Host to Slave

| UX_OTG_SLAVE_TO_IDLE
| 5
| Slave device is disconnected

| UX_OTG_SLAVE_TO_HOST
| 6
| Role swap from Slave to Host
|===

== Interrupt handlers

Both host and device controller drivers for OTG need interrupt handlers to monitor signals beyond traditional USB interrupts, in particular signals due to SRP and VBUS.

A controller integration can report these mode values:

* UX_OTG_MODE_IDLE
* UX_OTG_MODE_SLAVE
* UX_OTG_MODE_HOST

With a controller integration, the application can inspect the device type:

[,C]
----
_ux_system_otg -> ux_system_otg_device_type
----

Its values can be one of the following.

* UX_OTG_DEVICE_A
* UX_OTG_DEVICE_B
* UX_OTG_DEVICE_IDLE

With an HNP-capable controller integration, a host can request a role swap:

[,C]
----
/* Ask the stack to perform a HNP swap with the device. We relinquish the host role to A device. */

ux_host_stack_role_swap(storage ->ux_host_class_storage_device);
----

With the same integration, a device can request a role swap through its status response:

[,C]
----
/* We are a B device, ask for role swap. The next GET_STATUS from the host will get the status change and do the HNP. */

_ux_system_otg -> ux_system_otg_slave_role_swap_flag =
    UX_OTG_HOST_REQUEST_FLAG;
----
