== Description

=== Summary
The security fix for CVE-2025-0728 in eclipse-threadx NetX Duo refactors error handling in the HTTP server PUT process to use a shared cleanup label, but this unified cleanup path unconditionally calls `fx_file_close()` even when the file was never successfully opened. Multiple error branches jump to the shared cleanup label before any file open operation has occurred, causing `fx_file_close()` to operate on an uninitialized file handle, leading to undefined behavior, double-close issues, or memory corruption.

=== Details
The initial patch refactored error handling in the HTTP server PUT process to use a shared `put_process_end` cleanup label. However, several error branches that occur before the file is opened now jump to this label, which unconditionally calls `fx_file_close()`.

The specific problem is that early error conditions (e.g., malformed request, authentication failure) trigger a `goto put_process_end` before `fx_file_open()` is ever called. At the cleanup label, `fx_file_close()` is called on `server_ptr->nx_web_http_server_file`, which at that point contains uninitialized or zeroed memory, leading to undefined behavior in the filesystem layer.

**Vulnerable pattern:**
----
/* Early error before file is opened */
if (early_error) {
    goto put_process_end;   // File never opened!
}

/* ... file open happens here ... */
status = fx_file_open(&(server_ptr->nx_web_http_server_file), ...);

/* ... normal processing ... */

put_process_end:
    fx_file_close(&(server_ptr->nx_web_http_server_file));  // BUG: unconditional close
    return;
----

**Correct fix** -- track whether the file was successfully opened:

----
UINT status = NX_SUCCESS;
UINT file_opened = NX_FALSE;

/* ... error checking before file open ... */
if (early_error) {
    goto put_process_end;
}

/* Open the file */
status = fx_file_open(&(server_ptr->nx_web_http_server_file), ...);
if (status != NX_SUCCESS) {
    goto put_process_end;
}
file_opened = NX_TRUE;

/* ... normal processing ... */

put_process_end:
    /* Only close if file was actually opened */
    if (file_opened == NX_TRUE) {
        fx_file_close(&(server_ptr->nx_web_http_server_file));
    }
    return;
----

=== Impact
An attacker can send malformed HTTP PUT requests to a NetX Duo HTTP server to trigger early error paths that reach the cleanup label before the file has been opened. The unconditional `fx_file_close()` call on an uninitialized file handle causes undefined behavior in the filesystem layer, which on embedded systems can lead to crashes, memory corruption, or denial of service. Since this targets embedded RTOS devices, a crash may require physical intervention to recover, making this particularly impactful in IoT and industrial deployments.
